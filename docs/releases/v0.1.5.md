# Hop v0.1.5

[简体中文](v0.1.5.zh-CN.md) | **English**

Released 2026-07-29.

v0.1.5 turns Admin Web from a collection of management forms into a compact
operations surface while preserving Hop's single-binary, SQLite-first
deployment model.

## Highlights

### Faster daily administration

- Edit assets without losing list, search, or tag context.
- Copy target addresses directly from the inventory.
- Create and rotate credentials in focused drawers.
- Preserve existing encrypted secret fields when an edit leaves them blank.
- See credential usage and reassign assets before deletion.
- Review and copy Known Hosts fingerprints with an explicit trust-reset
  confirmation.

### Real operational data

- Dashboard gateway status for Admin, SSH, SQLite, version, and uptime.
- Asset health recorded from real SSH and TCP connection results.
- Recent SSH access and administrative changes.
- Action items for failed or unknown targets, missing credentials, missing SSH
  access, and partial data-source failures.
- Explainable credential, restricted-access, and Known Hosts coverage.

### Audit foundation

Administrative sign-in, password, asset, credential, SSH access, Known Hosts,
import, and administrator changes now write structured audit events. Event
details use allowlisted metadata and do not contain passwords, private keys,
passphrases, or uploaded secret contents.

The v0.1.5 Audit Logs page shows the latest 100 SSH sessions and 100
administrative events. Filtering, pagination, retention controls, and audit
export remain future work.

### Progressive team access

- A single administrator still signs in with only a password.
- The account field appears only after a second active administrator is added.
- Owner, Operator, and Viewer describe tasks instead of exposing an RBAC policy
  editor.
- Every administrator has an independent password.
- New administrators must replace a 12-character-or-longer temporary password
  on first login.
- Hop protects the last active Owner.
- Access or active-status changes invalidate the affected administrator's
  current sessions and create audit evidence.

## Compatibility

v0.1.5 applies SQLite migrations 005 and 006 on startup:

- Migration 005 adds administrator identity, audit event, and asset health
  storage.
- Migration 006 adds per-administrator password and access-level fields and
  copies the existing local admin password hash.

The migrations do not rewrite or delete existing assets, credentials,
authorized SSH keys, key-to-asset assignments, Known Hosts, or SSH sessions.
The existing local administrator becomes an Owner and keeps the current
password.

## Upgrade from v0.1.4

Treat Hop as access-critical infrastructure:

1. Arrange a management path that does not depend on Hop.
2. Download and verify the v0.1.5 artifact before the maintenance window.
3. Stop Hop.
4. Back up the entire persistent data directory and configuration.
5. Keep the v0.1.4 binary or image.
6. Start v0.1.5 and check logs.
7. Verify Admin login, inventory, SSH keys, credentials, and one real SSH path.

See the exact [deployment upgrade runbook](../deployment.md#upgrade).

## Rollback warning

After v0.1.5 applies migrations 005 and 006, a v0.1.4 binary rejects that
database because its migration set does not know those versions.

Rollback therefore requires both:

- the v0.1.4 binary or container image; and
- the complete pre-upgrade data backup, including `hop.db`, `hop.secret`, and
  `hop_host_key`.

Do not test rollback by pointing v0.1.4 at the migrated database.

## Known limitations

- Local passwords only; no OIDC.
- Fixed Owner, Operator, and Viewer levels; no custom policy editor.
- Admin sessions are in memory and expire after 30 minutes of inactivity.
- No audit filtering, pagination, export, or retention settings in v0.1.5.
- Asset health is updated by actual connection attempts rather than continuous
  background polling.
- No aggregated person entity for grouping several SSH keys.
