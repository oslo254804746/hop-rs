# Hop v0.3.0

[简体中文](v0.3.0.zh-CN.md) | **English**

v0.3.0 turns Hop into a zero-agent daily operations hub for personal developers and Multi-VPS operators: managed-mode port forwarding (`-L` / `-D` / Cursor & VS Code Remote-SSH over vault credentials), chained multi-hop `via_asset` relay across private subnets, parent-bound SFTP follow for interactive TUI sessions, one-click SSH key bootstrap, and scheduled RTT probing with Telegram / Bark / Webhook alerts — pairing `hop-rs`, `hop-rs-frontend`, and `luci-app-hop` at `v0.3.0`.

## Highlights

- **Managed-Mode Port Forwarding (`-L`, `-D`, Cursor / VS Code Remote-SSH)**: Clients authenticated against a managed SSH asset (`ssh -L ... <asset>@<hop-host>`, `ssh -D ... <asset>@<hop-host>`, or `--mode relay` in `~/.ssh/config`) can open `direct-tcpip` channels directly through Hop's vault-authenticated target SSH session without storing target keys or passwords locally. Controlled globally via `ssh.allow_managed_tcp_forwarding` (default `true`) and per asset via `allow_tcp_forwarding` (default `true`).
- **Chained Multi-Hop Relay (`via_asset`)**: SSH and TCP assets can route through an upstream managed SSH jump asset (`via_asset` in `hop.yaml`, `--via-asset` in CLI, `via_asset_id` in Control API / Web Panel) up to 4 hops deep with cycle detection and per-hop TOFU host-key verification across interactive shells, `exec`, SFTP, port forwarding, and zero-agent probes.
- **TUI-Selected Target SFTP Follow (`hop@<hop-host>`)**: GUI SSH clients (Netcatty, Xterminal, WindTerm, MobaXterm, etc.) entering the interactive TUI selector can open multiplexed or concurrent same-key/same-IP SFTP channels (even while the TUI menu is still waiting for Enter). Follower SFTP, `exec`, and port-forwarding channels automatically attach to the chosen target and close cleanly as soon as the TUI target session exits or disconnects.
- **One-Click SSH Key Bootstrap (`bootstrap-key`)**: Atomic 5-step zero-agent key onboarding (`POST /api/v1/assets/{id}/bootstrap-key` and `hop-server asset bootstrap-key <target>`): generates an Ed25519 keypair, installs `~/.ssh/authorized_keys` idempotently with `0700`/`0600` permissions, verifies a fresh second SSH connection with the new private key, rotates the asset's vault credential, and optionally hardens `sshd` `PasswordAuthentication` only after key login succeeds.
- **Scheduled Probing, RTT Sparklines & Multi-Channel Alerts**: Built-in background probe scheduler (`GET/PUT /api/v1/probe/settings`, `GET /api/v1/assets/probe-history`) with configurable interval, timeout, failure threshold, recovery notifications, RTT trend sparklines in the Web Panel, and encrypted **Telegram Bot**, **Bark (iOS Push)**, and **HMAC-SHA256 Webhook** alert channels (`GET/POST/PUT/DELETE /api/v1/notifications/channels` and `/test`).
- **Granular Diagnostics & Strict CSP Polish**: Records exact access and port-forwarding denial reasons on `sessions.error` and structured `audit_events` (`session.access_denied`, `session.forward_denied`), eliminates inline styles in the Web Panel for strict `style-src 'self'` CSP compliance, and proxies all new `v0.3.0` routes in `luci-app-hop` within its `< 256 KiB` package budget.

## Upgrade

- Existing `v0.2.x` SQLite databases are upgraded automatically and transactionally on first `v0.3.0` startup (`via_asset_id`, `allow_tcp_forwarding`, `asset_probe_samples`, `probe_settings`, and `notification_channels`).
- Back up `hop.yaml` and `data_dir` (`hop.db`, `hop.secret`, `hop_host_key`) as a pair before upgrading, then update `HOP_VERSION=v0.3.0` across `hop-rs`, `hop-rs-frontend`, and `luci-app-hop`.
