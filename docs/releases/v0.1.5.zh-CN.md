# Hop v0.1.5

**简体中文** | [English](v0.1.5.md)

发布于 2026-07-29。

v0.1.5 将 Admin Web 从一组管理表单提升为紧凑的运维界面，同时保持 Hop 单二进制、SQLite 优先的部署方式。

## 主要变化

### 更快的日常管理

- 编辑资产时保留当前列表、搜索和标签上下文。
- 从库存中直接复制目标地址。
- 使用抽屉创建和轮换凭据。
- 编辑时留空敏感字段会保留现有加密值。
- 删除凭据前显示使用情况，并要求先解除资产引用。
- 检查和复制 Known Hosts 指纹，通过显式确认保护信任重置。

### 真实运维数据

- Dashboard 展示 Admin、SSH、SQLite、版本和运行时间。
- 资产健康来自真实 SSH/TCP 连接结果。
- 展示近期 SSH 访问与管理变更。
- 对失败/未知资产、凭据缺口、SSH 入口缺口和数据源失败生成行动项。
- 提供可解释的凭据、受限访问和 Known Hosts 覆盖率。

### 审计数据底座

管理员登录、密码、资产、凭据、SSH 访问、Known Hosts、导入和管理员变更都会写入结构化审计事件。详情只使用白名单化元数据，不包含密码、私钥、passphrase 或上传的敏感内容。

v0.1.5 审计页展示最近 100 条 SSH 会话和 100 条管理事件。筛选、分页、留存设置和审计导出仍属于后续工作。

### 渐进式多人管理

- 单管理员继续使用密码直达。
- 只有添加第二位有效管理员后，登录页才显示账号名。
- Owner、Operator、Viewer 用任务语言描述权限，不暴露策略编辑器。
- 每位管理员拥有独立密码。
- 新管理员首次登录时必须更换至少 12 个字符的临时密码。
- Hop 保护最后一位有效 Owner。
- 修改访问级别或启用状态会撤销受影响管理员的当前会话，并写入审计。

## 兼容性

v0.1.5 启动时应用 SQLite 迁移 005 和 006：

- 005 新增管理员身份、审计事件和资产健康存储。
- 006 新增每位管理员独立密码与访问级别，并复制原本地管理员密码哈希。

迁移不会改写或删除现有资产、凭据、SSH 授权密钥、Key-to-Asset 分配、Known Hosts 或 SSH 会话。原本地管理员会成为 Owner，并保留现有密码。

## 从 v0.1.4 升级

应将 Hop 视为访问关键基础设施：

1. 准备一条不依赖 Hop 的备用管理路径。
2. 在维护窗口前下载并校验 v0.1.5。
3. 停止 Hop。
4. 备份整个持久化数据目录和配置。
5. 保留 v0.1.4 二进制或镜像。
6. 启动 v0.1.5 并检查日志。
7. 验证 Admin 登录、库存、SSH Key、凭据和一条真实 SSH 路径。

具体命令见 [Deployment Upgrade Runbook](../deployment.md#upgrade)。

## 回滚警告

v0.1.5 应用迁移 005 和 006 后，v0.1.4 会因为不认识这些迁移版本而拒绝打开该数据库。

因此回滚必须同时具备：

- v0.1.4 二进制或容器镜像；
- 升级前的完整数据备份，包括 `hop.db`、`hop.secret` 和 `hop_host_key`。

不能让 v0.1.4 直接打开已经迁移的数据库来测试回滚。

## 已知限制

- 仅支持本地密码，尚无 OIDC。
- 固定 Owner、Operator、Viewer，尚无自定义策略编辑器。
- Admin 会话保存在内存中，空闲 30 分钟后失效。
- v0.1.5 尚无审计筛选、分页、导出和留存设置。
- 资产健康由真实连接更新，而非持续后台轮询。
- 尚无聚合一个人多把 SSH Key 的 People 实体。
