# Hop v0.1.7

[简体中文](v0.1.7.zh-CN.md) | **English**

Released 2026-08-09.

v0.1.7 is a compatibility hotfix for managed remote commands, optional PTYs,
and SFTP against OpenSSH targets. It contains no database migration or
configuration-format change from v0.1.6.

## Fixed

Some OpenSSH servers increase the SSH channel window immediately after a
session channel opens. russh exposes that normal, informational packet as
`WindowAdjusted`. v0.1.6 expected the first target message to be only
`Success` or `Failure`, so it could abort setup with an error such as:

```text
unexpected target response to exec request:
WindowAdjusted { new_size: 2097152 }
```

v0.1.7 ignores informational window adjustments while continuing to wait for
the actual request reply. The original connect timeout remains a single budget;
window updates cannot reset or extend it. Explicit rejection, channel closure,
unexpected messages, and timeout errors retain their previous behavior.

The fix applies to every managed request that waits for a target reply:

- optional PTY allocation for remote commands;
- remote-command execution; and
- SFTP subsystem startup.

Managed stdin, stdout, stderr, exit status, exit signal, session auditing, and
administrator termination behavior are otherwise unchanged.

## Authentication banners and automation

An SSH authentication banner is sent before a client selects interactive
shell, exec, or subsystem mode. A configured `ssh.banner` therefore appears on
stderr for remote commands and file transfer as well as interactive sessions.
For automation that requires clean stderr, use:

```toml
[ssh]
banner = ""
```

This is an operator choice rather than an automatic v0.1.7 configuration
rewrite; existing banner values are preserved during upgrade.

## Compatibility and upgrade

- No SQLite migration is added in v0.1.7.
- No configuration key is added or removed.
- Existing assets, credentials, authorized keys, Known Hosts, audit events,
  and sessions are preserved.
- Stop Hop, back up the persistent data and configuration, install v0.1.7,
  then verify one interactive connection and one remote command.

See the [deployment upgrade runbook](../deployment.md#upgrade).
