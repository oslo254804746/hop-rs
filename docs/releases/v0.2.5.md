# Hop v0.2.5

[简体中文](v0.2.5.zh-CN.md) | **English**

Released 2026-08-25.

v0.2.5 is an SSH interoperability and security maintenance release. It
contains no SQLite migration, configuration-format change, or panel feature
change.

## Fixed

Termius on iOS can advertise an SSH `first_kex_packet_follows` guess for a
key-exchange algorithm that the server does not implement. The SSH protocol
requires the peer to ignore that guessed packet when the guess is wrong. The
previous russh version could consume it as the next message and report:

```text
SshEncoding: character encoding invalid
```

Hop now uses russh 0.63.1, which contains the upstream fix and regression test
for this unknown-KEX guess path. The fix is at the SSH KEXINIT layer; it is not
an interactive terminal or UTF-8 setting. Existing OpenSSH, key, PTY, exec,
SCP/SFTP, ProxyJump, and TCP forwarding behavior remains supported.

## Security and dependency update

russh is upgraded from 0.61.1 to the exact 0.63.1 release. Besides the KEX
compatibility fix, this release includes upstream security fixes that validate
server-supplied channel IDs before client-side handler callbacks and prevent a
MAC-required block cipher from being negotiated without a MAC and panicking.

## Compatibility and upgrade

- No SQLite migration or database-format change is included.
- No configuration key is added, removed, or rewritten.
- Stop Hop, back up the persistent data and configuration, set
  `HOP_VERSION=v0.2.5`, and start the Compose deployment. Verify one Termius
  iOS connection and one existing OpenSSH connection after the restart.
- Compose uses the same matching `HOP_VERSION` tag for `hop-rs` and
  `hop-rs-frontend`; the panel image has no functional changes in v0.2.5.

If a rollback is required, stop Hop and set `HOP_VERSION=v0.2.4` to restore the
previous matching backend and panel images. Because v0.2.5 adds no migration
or persistent-format change, the existing database can be reused; restore the
backup when reverting any unrelated configuration or data changes.

## Release artifacts

For containers, pin the matching images to `v0.2.5` rather than `latest`.
Always keep a copy of the previous image tag and configuration before an
upgrade so the rollback can be performed without network access.
