# Hop v0.1.7

**简体中文** | [English](v0.1.7.md)

发布于 2026-08-09。

v0.1.7 是面向 OpenSSH 目标的兼容性热修复，涉及托管远程命令、可选 PTY 和 SFTP。相较 v0.1.6，本版本没有新增数据库迁移，也没有修改配置格式。

## 修复内容

部分 OpenSSH 服务器会在会话通道打开后立即增大 SSH 通道窗口。russh 将这个正常的信息性数据包暴露为 `WindowAdjusted`。v0.1.6 要求目标返回的第一条消息只能是 `Success` 或 `Failure`，因此可能以如下错误中止：

```text
unexpected target response to exec request:
WindowAdjusted { new_size: 2097152 }
```

v0.1.7 会忽略信息性的窗口调整，并继续等待真正的请求回复。原连接超时仍是单一预算；窗口更新不会重置或延长超时。明确拒绝、通道关闭、意外消息和超时的错误行为保持不变。

该修复覆盖所有需要等待目标回复的托管请求：

- 远程命令的可选 PTY 分配；
- 远程命令执行；
- SFTP 子系统启动。

托管 stdin、stdout、stderr、退出码、退出信号、会话审计和管理员终止行为均保持不变。

## 认证 banner 与自动化

SSH 认证 banner 会在客户端选择交互式 shell、exec 或子系统模式之前发送。因此，配置的 `ssh.banner` 会出现在远程命令、文件传输和交互式会话的 stderr 中。自动化需要纯净 stderr 时，请使用：

```toml
[ssh]
banner = ""
```

这是运维人员的显式选择，v0.1.7 不会自动改写配置；升级时会保留现有 banner 值。

## 兼容性与升级

- v0.1.7 不新增 SQLite 迁移。
- 不新增或删除配置项。
- 现有资产、凭据、SSH 授权密钥、Known Hosts、审计事件和会话都会保留。
- 停止 Hop，备份持久化数据和配置，安装 v0.1.7，然后验证一条交互式连接和一条远程命令。

具体命令见 [Deployment Upgrade Runbook](../deployment.md#upgrade)。
